# raptor-runtime - Runtime Engine spec
Owns: hardware detection, llama.cpp runtime manifests/install, llama-server lifecycle, GPU verification, memory-aware config, performance memory.
[MUST] items are release blockers.

Modules
- `hardware`: `HardwareInfo { os, cpu{brand,cores,threads,features[avx2,avx512,...]}, ram_total/avail, gpus[GpuInfo{vendor,name,vram_total,vram_free,arch (e.g. gfx1200),driver}] }`.
  Detect behind a `HardwareProbe` trait (real impl + `FakeProbe`). Windows GPU via PowerShell/DXGI output parsing; Linux via `/sys`, `rocm-smi`, `lspci` parsing. Parsers are pure fns tested with captured sample outputs (include RX 9060 XT gfx1200, NVIDIA, Intel iGPU, CPU-only). [MUST] identify RX 9060 XT / gfx1200.
- `manifest`: runtime manifest (JSON, signature-ready): runtime id, version, llama.cpp build, backend (hip/vulkan/cuda/cpu), os, supported gfx archs, url, sha256, min driver. `select_runtime(&HardwareInfo, &[Manifest]) -> Selection{manifest, reason, degraded}`; if no GPU backend is compatible return explicit CPU selection with `degraded=true` and reason - never silent. Install = download + sha256 verify + atomic extract into `DataDirs::runtimes()/<id>/<ver>`; keep previous version; `rollback()`. Download via trait `Fetcher` (fake in tests). Reject zip-slip paths.
- `config`: `LaunchConfig` builder -> llama-server args: model path, `-ngl`, ctx, batch/ubatch, threads, flash-attn (only if backend supports), KV cache type (f16/q8_0/q4_0), host/port (default 127.0.0.1), api-key. `recommend(&HardwareInfo, &ModelMeta{size_bytes,n_layers,n_ctx_train,kv dims}, ctx_target) -> Recommendation{config, rationale: Vec<String>}`: VRAM-aware with headroom (reserve >= max(10%, 512MB)), estimates KV cache bytes, reduces ctx or offloaded layers before OOM, explains every decision.
- `process`: `ServerManager` start/stop/restart/health. Spawns llama-server via `Spawner` trait (fake in tests), captures stdout/stderr into a ring buffer + structured log, polls `/health` and `/v1/models` with timeout, crash detection -> bounded auto-restart with backoff, graceful shutdown (kill whole process tree on Windows), no orphans. States: Stopped, Starting, Ready, Degraded, Crashed(reason). Load failure -> diagnostics from log (OOM, unsupported arch, missing file, port in use).
- `verify` [MUST]: `parse_server_log(&str) -> LogFacts{backend, devices, layers_offloaded, layers_total, flash_attn,...}` pure parser tested on realistic llama.cpp log fixtures (HIP/ROCm, CUDA, Vulkan, CPU-only). `GpuVerdict::{Verified{evidence}, CpuOnly{reason}, Unverified{reason}}`. GPU requested but 0 layers offloaded => `CpuOnly` with loud warning. Optional `GpuTelemetry` trait for VRAM/utilization evidence.
- `perfmem`: JSON store of known-good configs + benchmark records keyed by (machine fingerprint, model hash, runtime id): ttft, prompt tok/s, gen tok/s, vram, ram, ctx, stable flag. `best_known`, `compare`, never replace a known-good with an unstable one, dedupe repeat benchmarks. Atomic writes (tmp + rename), versioned schema + migration fn.
- `tokenizer`: `ServerTokenCounter` implementing `raptor_core::TokenCounter` via llama-server `/tokenize` (HTTP behind a trait; fall back to `EstimatingCounter`, clearly flagged inexact).

Tests: >= 40 meaningful unit tests; parsers table-driven; process manager tested with a fake spawner (crash / restart / health-timeout / port-in-use).
Facade: `RuntimeEngine` struct in lib.rs (built from `DataDirs` + trait objects) with ~6 methods: `detect_hardware, ensure_runtime, recommend_config, load_model, unload, status`.
