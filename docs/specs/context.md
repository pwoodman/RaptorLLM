# raptor-context - Context Intelligence Engine spec (HIGHEST STRATEGIC PRIORITY)
First-class product. Owns: repo indexing, code graph, retrieval, budgeting/packing, conversation memory, provenance, recovery.

NON-NEGOTIABLE: never silently discard system instructions, active task requirements, files being edited, active diffs, unresolved test/error output. Protected items may exceed the budget -> report `over_budget_by` loudly; never drop them.

Modules
- `scan`: walk repo (`ignore` crate: .gitignore + `.raptorignore`), exclude generated/binary/vendor/lockfiles/huge files/secrets (.env, keys) recording the exclusion reason; content hash (sha256 or blake3). Incremental: `Index::update()` re-parses only files whose hash changed; monorepo-friendly (streaming, no whole-repo strings in memory). Git awareness: changed/staged/untracked via `git status --porcelain` behind trait `GitProbe` (fake in tests) + recency from git log.
- `parse`: language detection + symbol/import extraction behind an `Extractor` trait. Use tree-sitter (rust, python, ts/js, go, java, c/cpp) if grammars build on Windows without extra toolchains; otherwise robust regex extractors behind the same trait with tree-sitter slotted in later. Output: `Symbol{name,kind,range,parent}`, `Import{raw,resolved_path?}`, best-effort call refs, test detection and test->subject mapping.
- `graph`: dependency/import graph + symbol relations (defines, imports, calls, tested_by). Queries: callers, callees, dependents (downstream impact), related tests, neighbourhood(k hops). Incremental edge invalidation. Persist to `DataDirs::context_index()`, versioned.
- `retrieve`: lexical BM25 over identifiers+text, symbol-name search, graph-proximity boost, recency/git-change boost, pin boost; trait `Embedder` (ship `NoEmbedder` + hook) with hybrid fusion (RRF). `TaskKind::{Debug,Architecture,Refactor,Feature,Ui,Security,Performance}` -> different scoring weights and category budgets.
- `budget`/`pack`: takes `raptor_core::TokenCounter` (flag `tokens_exact` in output), model context size, reserved output tokens. Categories: instructions, task, active_files, diffs, errors_tests, retrieved_code, graph_neighbours, memory, history. Dynamic allocation by TaskKind; protected-first; intelligent truncation of unprotected items (keep signature+docstring+relevant symbol bodies before dropping; elide with markers, never mid-token); NOT oldest-message removal. Deterministic.
- `provenance`: `ContextManifest { included: [Item{id,source,hash,range,tokens,category,score,why}], excluded: [{id,why,tokens,recover_handle}], utilization_by_category, over_budget_by, tokens_exact, warnings }`. Every item explains why it is in/out.
- `recovery`: `recover(handle|query, extra_budget) -> Items`: an agent that finds something missing gets it without rebuilding the whole context. Handles are stable while the hash is unchanged; stale handle => explicit `Stale` error.
- `memory`: model-independent conversation memory: decisions, conventions, completed-work summaries (with source file hashes), failed attempts. `invalidate_stale()` when referenced file hashes change (marked stale, never served as current). Detect repeated failed attempts / circular reasoning (similar repeated tool calls/errors) -> warning. Summarisation via trait `Summarizer` (fake in tests); decisions survive summarisation (structured `decisions` list kept verbatim).
- `api`: `ContextEngine` facade with harness-independent serde types: `build_context(ContextRequest{workspace, task, task_kind, messages, active_files, model_ctx, ...}) -> ContextResponse{messages, manifest}`, `search`, `symbols`, `recover`, `impact(file)`, `index_status`. Types must map 1:1 to MCP tools (the gateway exposes them).

Tests: >= 60 unit tests plus an evaluation test over a fixture repo (built in a tempdir) proving: relevant-code recall beats recency-only truncation; protected items never dropped even with a tiny budget; stale summary invalidated after a file edit; manifest explains every item; incremental update reparses only changed files.
